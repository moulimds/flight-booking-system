# Flight Booking System

## Overview

The Flight Booking System is a microservices-based application developed using Java and Spring Boot. The project is designed to handle the main operations involved in a flight reservation system, including user authentication, flight search, seat selection, booking, payment, invoice generation, and notifications.

The application is divided into multiple independent services. Each service is responsible for a specific business function and communicates with other services through REST APIs and asynchronous messaging where required.

## Features

* User registration and email verification
* User login and JWT-based authentication
* Flight creation and management
* Flight search
* Fare management and price calculation
* Seat availability and reservation
* Support for Economy, Premium Economy, Business, and First Class
* Passenger and booking management
* Payment processing and refunds
* Invoice generation in PDF format
* Email notifications
* Passenger check-in
* Service discovery using Eureka
* Centralized configuration using Config Server
* API Gateway for routing and request handling
* Asynchronous communication using RabbitMQ

## Architecture

The project follows a microservices architecture. The main services are:

### API Gateway

The API Gateway acts as the entry point for client requests. It routes requests to the appropriate microservice and also handles common gateway-level security requirements.

### Auth Service

The Auth Service manages user accounts and authentication.

Responsibilities include:

* User registration
* Email verification
* Login
* JWT token generation
* Password reset
* User management

### Flight Service

The Flight Service manages flight information.

Responsibilities include:

* Creating flights
* Updating flight details
* Deleting flights
* Managing flight status
* Maintaining flight capacity

### Search Service

The Search Service handles flight search operations and retrieves the required flight and fare information based on the search criteria.

### Fare Service

The Fare Service manages ticket pricing and fare-related operations.

Responsibilities include:

* Creating and updating fares
* Calculating prices
* Validating fares
* Managing fare rules
* Supporting different fare types

### Seat Service

The Seat Service manages seat inventory and availability.

It handles:

* Available seats
* Seat holds
* Seat reservations
* Seat releases
* Seat blocking and unblocking
* Seat status management

The system supports four cabin classes:

* Economy
* Premium Economy
* Business
* First Class

### Booking Service

The Booking Service manages the booking lifecycle.

Responsibilities include:

* Creating bookings
* Holding bookings
* Confirming bookings
* Cancelling bookings
* Managing passenger information
* Generating booking references and PNR
* Maintaining booking status history
* Validating fares

### Payment Service

The Payment Service handles payment-related operations.

Responsibilities include:

* Processing payments
* Maintaining payment status
* Managing refunds
* Publishing payment events

### Invoice Service

The Invoice Service generates and manages invoices after successful payments. It also supports PDF invoice generation using OpenPDF.

### Notification Service

The Notification Service handles notifications generated by other services.

It is responsible for:

* Booking confirmation emails
* Payment-related notifications
* Flight notifications
* Email delivery
* Notification logging

RabbitMQ is used to receive events from other services.

### Check-in Service

The Check-in Service manages passenger check-in operations, including baggage information, seat details, and check-in status.

### Eureka Server

Eureka is used for service discovery. Each microservice registers itself with the Eureka Server, allowing services to discover each other without relying on fixed service addresses.

### Config Server

The Config Server provides centralized configuration for the microservices. This allows common configuration properties to be maintained separately from the individual services.

## Communication Between Services

The application uses two main approaches for communication.

### REST Communication

REST APIs are used when a service needs an immediate response from another service.

For example, the Search Service can communicate with the Flight and Fare Services to retrieve the information required for a flight search.

### RabbitMQ

RabbitMQ is used for asynchronous event-based communication.

For example:

```text
Payment Service
       |
       v
Payment Event
       |
       v
RabbitMQ
       |
       +-------------> Invoice Service
       |
       +-------------> Notification Service
```

This reduces direct dependency between services and allows event consumers to process events independently.

## Running the Project

### Prerequisites

The following software is required:

* Java 21
* Maven
* MySQL
* RabbitMQ
* Docker Desktop
* Git

### Clone the Repository

```bash
git clone https://github.com/moulimds/flight-booking-system.git
cd flight-booking-system
```

### Build a Service

Navigate to the required service and run:

```bash
mvn clean install
```

### Starting the Services

The infrastructure services should generally be started before the business services:

```text
1. Config Server
2. Eureka Server
3. API Gateway
4. Auth Service
5. Flight Service
6. Search Service
7. Fare Service
8. Seat Service
9. Booking Service
10. Payment Service
11. Invoice Service
12. Notification Service
13. Check-in Service
```

## Project Objective

The main objective of this project is to develop a flight booking application while demonstrating how a real-world system can be divided into independent microservices.

The project focuses on service separation, secure authentication, database management, inter-service communication, asynchronous event processing, centralized configuration, service discovery, and API integration.
